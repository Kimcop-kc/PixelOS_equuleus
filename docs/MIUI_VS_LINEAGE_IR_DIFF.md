## 4. The one real difference, explained

`lib/libmmcamera_faceproc.so`: same size (1,246,516), **3 bytes** differ, at
offsets `0x7FE0`, `0x7FE2`, `0x7FE4` — values `0x03 0x03 0x03` in MIUI versus
`0x01 0x01 0x01` in LineageOS.

Those offsets fall in the ELF symbol-version table. LineageOS's own
`device/xiaomi/equuleus/extract-files.py` declares:

```python
'vendor/lib/libmmcamera_faceproc.so': blob_fixup()
    .clear_symbol_version('__aeabi_memcpy')
    .clear_symbol_version('__aeabi_memset')
    .clear_symbol_version('__gnu_Unwind_Find_exidx'),
```

Three symbols, three bytes, values lowered to the unversioned default. This is a
**LineageOS fixup applied to the MIUI blob**, not a content divergence between
the two ROMs.

Practical consequence: the LineageOS copy is the corrected one. Replacing it with
MIUI's raw copy would reintroduce the symbol-version problem that fixup exists to
solve — which is precisely what the task forbids ("不能直接覆盖已经正常适配的
LineageOS 驱动").

## 5. Version comparison

There is no version skew to report, because there is no second version: the files
are the same bytes. Where a version is visible at all:

| Item | MIUI | LineageOS |
| --- | --- | --- |
| Firmware base | `V12.5.2.0.QECCNXM` (Android 10) | LineageOS 22.2 (Android 15) |
| OV9282 sensor driver | same blob | same blob |
| Camera HAL | same blob | same blob |
| `camxoverridesettings.txt` | same 856 bytes | same |

The platform moved from Android 10 to Android 15, but **the camera blob set did
not change** — it is still the Android 10 vendor blob, which is exactly why the
reuse question has a clean answer.

## 7. Verdict

**No MIUI component needs to be added to this device tree for IR face unlock.**

Every IR-critical file is already present and byte-identical, with matching
architecture, SONAME and dependencies. The two MIUI-only paths are either
unreferenced (64-bit faceproc) or built from source in this platform (camera
provider service). The single byte-difference is LineageOS's own fixup and must be
preserved.

Therefore **no blob patch is emitted** — see `IR_FACE_UNLOCK_DEPENDENCIES.md` §6.
Emitting a patch that overwrote LineageOS blobs with MIUI bytes would be an
active regression.

**NOT VERIFIED** on hardware: none of this proves the IR camera opens, that the
emitter fires, or that unlock works in the dark.
